# Session Storage

Внешнее хранилище сессий через callback-free `session_storage/v2`.
`proteus-core` не является зависимостью реализации. Общие DTO принадлежат
`proteus-contracts`, проверка канонических фактов — `proteus-session-semantics`.

Доступны две самостоятельные реализации:

- `jsonl`: существующий `journal.jsonl` schema 21, отдельные content-addressed
  blobs, `session.json` schema 4. Сохранённые сессии читаются без переписывания.
- `sqlite`: канонический журнал в `journal.sqlite`, WAL и `synchronous=FULL`.
  JSONL для этой реализации не создаётся. SQLite-кеш старого Core не используется
  как источник канонических фактов.

Core явно выбирает реализацию в конфигурации. Открытие сессии другим backend
без явного переноса данных возвращает ошибку, а не пустую историю. Реализации не вызывают модель,
инструменты или другие host callbacks и не выбирают политику сжатия контекста.

## Запись И Восстановление

Перед отправкой Core назначает стабильный `operation_id`, timestamp и ожидаемые
`session_seq` / `history_revision`. Эти счётчики различны: не каждый факт
изменяет историю. `operation_id` сохраняется как `record_id` в той же транзакции.
ACK возвращается только после durable commit. После потери транспорта Core
может запросить `CommitStatus`; идентичный повтор возвращает прежний ACK,
изменённое содержимое с тем же id отвергается.

Отдельные writer handles имеют разные tokens и разделяют одну OS-lease сессии.
Последний release освобождает lease; hibernate сбрасывает декодированное состояние,
сохраняя lease. Lock inode остаётся вне удаляемой папки. Generation и durable
receipts удаления не позволяют старому handle удалить или изменить новую сессию.
Opaque locator также хранит incarnation: после удаления только новый явный Create
может зарезервировать следующую incarnation; старый pre-create handle не может
воскресить папку после перезапуска. Незавершённое удаление сначала согласуется
повтором того же Delete.

Read-only snapshots не берут writer lease и фиксируют точный committed prefix.
Их handles ограничены 32 на сервис. Тёплое открытие использует проверенный
fingerprint и файловые stamps; первый доступ к каноническим данным проверяет
полный prefix. Последовательные страницы затем читаются одним проходом с одним
pending record, без повторного декодирования хвоста. Изменение JSONL-файла
сбрасывает подтверждение prefix и требует повторной проверки. `CompareSnapshots` принимает descriptor
старого prefix после освобождения старого handle. Строгий проход сохраняет
одну предыдущую границу: её ревизию, SHA-256 и позицию конца строки. При
сравнении этой границы проверяются все фиксированные байты JSONL; SQLite
сохраняет read transaction. Если журнал ссылается на внешние payload, остаётся
полный повторный проход с проверкой blobs. Тёплый descriptor сам по себе не
подтверждает границу. При чтении первой страницы после известной границы JSONL
может продолжить декодирование с её позиции после проверки всего фиксированного
диапазона; короткий prefix перед большим хвостом читается обычным способом.
Страницы ограничены числом
записей и 4 MiB суммарных canonical payloads; одна большая запись возвращается
целиком, максимум 65 MiB. Процессному компоненту необходим согласованный frame
budget для таких записей; данные не обрезаются.

Компонент объявляет optional feature `display_projection`. При потере
сохранённого представления `OpenDisplaySnapshot` за один строгий проход
восстанавливает conversation, usage и model context и сохраняет только записи
для отображения во временный файл. `ReadDisplayRecords` читает этот файл,
сохраняя исходные sequence numbers с пропусками диагностических записей.
Открытый snapshot владеет файлом до release или вытеснения. Временный файл
ограничен 512 MiB, возвращаемое состояние — 32 MiB. Невозможность подготовить
такое представление возвращает пустой результат для обычного восстановления;
повреждение канонического журнала возвращает ошибку. Запросы исполнения и replay
используют полную проверку выбранного хранилища.

Только writer recovery чинит незавершённый JSONL tail. Полная повреждённая
строка не считается tail и приводит к ошибке. Read-only просмотр ничего
не чинит. История до замены читается по generic part identity, без разбора
формата OpenAI или другого провайдера.

## Каталог

При отсутствии проверенного индекса `List` читает журнал, не удерживая общий
mutex сервиса. Одновременно выполняется не более одного обхода каталога на
экземпляр хранилища. Перед публикацией результата модуль заново проверяет
incarnation, метки журнала/metadata и состав blobs. Изменившаяся сессия
проверяется повторно под общей блокировкой; удалённая или пересозданная не
получает старый индекс. Если проверить полный состав blobs нельзя, чтение
этой сессии сразу выполняется под общей блокировкой. Обычный список
пропускает ошибочные сессии, а аудит возвращает ошибку и не доверяет кешу.

## Metadata, Blobs И Кеши

Metadata CAS хранит ссылку на content-addressed значение и receipt операции одним
atomic replace. Существующие отдельные `*.json` metadata-файлы импортируются при
первом обращении по прежнему имени; envelope становится authority, а tombstone
не даёт удалённому значению воскреснуть из старого файла. Общий
metadata envelope ограничен 16 MiB. Blobs адресуются SHA-256 с проверкой размера
и содержимого. Disposable caches не требуют writer lease, привязаны к session,
revision и fingerprint prefix; transient snapshot handle в сравнении не участвует.
Суммарный кеш сессии ограничен 128 MiB, старые поколения удаляются по времени
записи. Потеря кеша — cache miss, а не потеря истории. Запись кеша не создаёт
родительские каталоги и не может воскресить удалённую сессию.

JSONL и SQLite сохраняют совпадающий итог хука ссылкой на его исходное событие.
Повторяющиеся большие массивы сообщений внутри трассы имеют одну копию.
При чтении модуль восстанавливает поля для проверки журнала и replay.
SQLite хранит трассу целиком в своей строке. В JSONL внешние payloads используют
общие фрагменты внутри каталога сессии, в том числе между разными событиями.

## Уплотнение Архива

`proteus-session-storage-module --compact-archive /absolute/session-directory`
уплотняет внешние payloads существующей JSONL-сессии. Команда получает обычный
writer lease, проверяет исходные SHA-256 и точное восстановление payload перед
atomic replace каждого файла. Журнал, record ids и ссылки сохраняются. Повторный
запуск продолжает незавершённую обработку. После уплотнения команда подготавливает
каталог только этой сессии, чтобы следующий запуск использовал сохранённый индекс.
JSON-результат содержит размеры исходных payloads, оставшихся файлов и общих chunks.
Общие chunks публикуются перед ссылающимся на них файлом. Старые бинарники без
поддержки формата shared blobs должны быть обновлены перед чтением такого архива.

## Проверка

`cargo test -p session-storage -p proteus-session-storage-module` проверяет оба
backend через один контракт, включая idempotency, snapshot/lease/CAS, corruption,
холодное открытие, ограничение страниц и потерю ACK при убийстве настоящего
SDK-процесса. Тесты не запускают модель и не делают платных запросов.
