## Границы

ContextBuilderModuleHost не предоставляет callback cancellation: здесь введён
локальный deadline, а новый wire callback не добавлен. Ptyxis по-прежнему
сохраняет полный вывод во временные capture-файлы; disk quota этим исправлением
не обещается. Для ограниченного сохранения нужен обычный source_capture.

Отдельных claims об ускорении, RSS/CPU, live provider interoperability и
нативном UI нет. Исследовательские DCP/tool-output-artifacts исключены из
shipping scope. Документированные ограниченные shell semantics OpenCode и
pinned patch semantics не переписывались как якобы новые дефекты.

После исправления G4 весь target `codex_model_resume` повторён: 57 passed.
В one-shot cancellation oracle leaf-потомок самостоятельно сохраняет
`/proc/self/stat`, сигнал готовности и отложенный marker. До отмены
подтверждается живая PID/starttime identity; после — её исчезновение или
terminal state, без marker. Это различает смерть shell-родителя и реальное
завершение потомка, а starttime исключает ошибку от повторного использования
PID. Leaf живёт не более секунды в обычном сценарии, без оставленного
20-секундного процесса при раннем assertion failure.

Отдельный отрицательный контроль действительно убил только родительский
shell: потомок записал собственный `late-marker`, завершился с кодом 0 и был
reaped тестовым subreaper. Значит, такой дефект больше не даёт ложный PASS
за счёт того, что marker раньше принадлежал уже убитому родителю. Python18,
Node33, rustfmt и diff-check также прошли в этой заключительной проверке.
